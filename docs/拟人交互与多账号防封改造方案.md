# Maa_MHXY_MG 拟人交互与多账号防封改造方案及执行规划

## 1. 项目背景与改造目标

### 1.1 业务场景定义
* **运行形态**：单台 PC 设备、单一局域网公网 IP 下，通过安卓模拟器多开同时运行 5 个游戏账号（1 队长 + 4 队员）。
* **业务原则**：
  * **保持既有业务链路不变**：不打乱各账号每天固定的任务执行顺序（如师门、副本、捉鬼、运镖等），保留现有一键预设配置。
  * **零功能破坏**：所有 OCR 文字识别、图像模板匹配（TemplateMatch）及任务状态机跳转逻辑保持 100% 兼容。

### 1.2 核心改造指标
1. **输入合法化**：完全消除向安卓底层投递 PC 快捷键（`ClickKey` Alt 组合键）的高危行为。
2. **落点与触控拟人化**：消除几何中心绝对点击（零方差）与瞬间点击（0ms），注入二维截断高斯随机落点、人手按压保持时间（Dwell Time）以及肌肉微颤抖。
3. **滑动轨迹拟人化**：将固定坐标的匀速直线滑动替换为三阶贝塞尔弧形曲线与加减速速度模型。
4. **单人单鼠标时序互斥**：在 5 个并发运行的进程间建立“单人注意力调度器”，杜绝 5 个账号在同一毫秒产生物理并发点击，完整复现“单一真人手持一只鼠标在 5 个窗口间快速轮流操作”的现实物理特征。

## 2. 现有逻辑风控薄弱点审查结论

| 维度 | 现有代码现状 | 风控触发机制与隐患 | 改造方向 |
| :--- | :--- | :--- | :--- |
| **底层按键** | `assets/resource/base/pipeline/*.json` 中大量使用 `ClickKey: [57, 31]` 等 Alt 组合键 | 移动端原生反作弊监听 `dispatchKeyEvent`，手游产生 PC 快捷键属于高危异常 | 挂载 `ClickkeyChangeClick.json` 覆盖层，转为界面图标真实点击 |
| **点击落点** | 自定义动作与识别中普遍使用 `center_x = box[0] + box[2] // 2` 或硬编码坐标 | 坐标方差 $\sigma \to 0$，长期点击绝对几何中心直接命中离线特征检测 | 引入二维截断高斯分布算法，按安全边距生成随机落点 |
| **触控动态** | 底层 ADB `post_click` 为瞬间 `input tap`，按下到抬起时长近乎 0ms | 缺少人类手指肉垫按压屏幕的时间（Dwell Time）和生理微动 | 封装 `post_touch_down` + 随机保持 65~125ms + 微颤抖 + `post_touch_up` |
| **滑动轨迹** | 如 `baotu_renwu.json` 等文件中起点终点为 1 像素，时长固定 500ms | 绝对匀速几何直线，缺乏人手拇指转动的弧度和加减速曲线 | 采用三阶贝塞尔曲线插值 + SmoothStep S型速度平滑 |
| **多号并发** | 5 个 MAA 实例独立运行，多进程可能在同一毫秒下发点击 | 单人操作 5 个窗口不可能同毫秒下发多次点击，并发暴露多线程外挂 | 引入跨进程注意力文件锁，强制产生 200~500ms 视线与鼠标位移延时 |
| **答题认知** | `AIAnswer.py`、`reco_sjqy.py` 中识别后固定 `time.sleep(2)` 即交卷 | 无论题目长短耗时完全相同，缺乏人类阅读与思考的生理耗时分布 | 引入基于题干与选项字符长度的对数正态随机认知延时模型 |

## 3. 架构设计与模块拆分

系统自底向上划分为四个独立模块：

```
┌────────────────────────────────────────────────────────┐
│ 4. 业务层适配模块 (Custom Action / Recognition)        │
│    - reco_sjqy / AIAnswer / returnOCR / shimen 等      │
├────────────────────────────────────────────────────────┤
│ 3. 全局单人注意力调度模块 (Attention Coordinator)       │
│    - 基于 IPC 文件锁的跨进程单鼠标互斥与视线转移时延   │
├────────────────────────────────────────────────────────┤
│ 2. 底层拟人触控核心模块 (Human Touch Core)             │
│    - 二维截断高斯落点 / 真实按压 Dwell / 贝塞尔弧形滑动│
├────────────────────────────────────────────────────────┤
│ 1. 资源配置层改造模块 (Pipeline Resource Layer)        │
│    - 启用 ClickkeyChangeClick 覆盖，根除 ClickKey      │
└────────────────────────────────────────────────────────┘
```

### 3.1 模块 1：资源配置层改造（Pipeline Resource Layer）
* **涉及路径**：`assets/interface.json`、`assets/resource/base/pipeline/`、`assets/resource/mac/pipeline/`
* **职能**：
  * 项目中已存在 1299 行的完整按键平替文件 `assets/resource/mac/pipeline/ClickkeyChangeClick.json`。
  * 将该覆盖规则无侵入地引入默认 ADB 控制器资源路径，将全部 65 处 `ClickKey` 平替为真实界面的图标点击。
* **边界**：仅调整资源路径或文件组织结构，不变更 pipeline 的前后置逻辑节点（Next / JumpBack）。

### 3.2 模块 2：底层拟人触控核心模块（Human Touch Core）
* **涉及路径**：`agent/utils/human_touch.py`（新增）
* **职能**：
  * **落点生成**：`get_human_click_point(box, margin_ratio=0.15)`，以目标框中心为均值、宽高安全内缩后计算截断二维正态分布。
  * **物理点击**：`human_click(controller, box, pre_wait, post_wait)`，组合 `post_touch_down` $\to$ 保持 65~125ms（含 40% 概率的 1px 微抖动） $\to$ `post_touch_up`。
  * **拟人滑动**：`human_swipe(controller, start_box, end_box, duration_ms)`，生成三阶贝塞尔手势弧线，使用 SmoothStep 模拟先加速后减速。
* **边界**：通用工具库，纯函数式驱动 `context.tasker.controller`，不依赖任何特定业务任务。

### 3.3 模块 3：全局单人注意力调度模块（Attention Coordinator）
* **涉及路径**：`agent/utils/attention_coordinator.py`（新增）
* **职能**：
  * 复用 `agent/utils/utils.py` 中的跨进程文件锁（`msvcrt` / `fcntl`）。
  * 维护跨进程的全局时间戳记录（`last_action.stamp`）。
  * 任何实例在下发点击/滑动时必须先申请注意力锁；若检测到上一次动作由其他实例产生，强制注入 250ms ~ 550ms 的人类视线与鼠标位移物理时延。
* **边界**：跨进程互斥组件，提供上下文管理器（`with AttentionCoordinator.acquire(instance_id):`）。

### 3.4 模块 4：业务层自定义动作与识别重构（Custom Actions & Recognitions）
* **涉及路径**：
  * `agent/custom/recognition/reco_sjqy.py`（三界奇缘）
  * `agent/custom/recognition/AIAnswer.py`（科举乡试）
  * `agent/custom/action/returnOCR.py`（OCR 通用点击）
  * `agent/custom/recognition/shimen_renwu.py`（师门任务）
  * `agent/custom/action/sanjieqiyuan.py` 等硬编码点击点
* **职能**：
  * 剥离所有显式计算的中心点坐标 `(box[0] + box[2] // 2)` 与硬编码单像素点（如 `(500, 344)`、`(34, 137)`）。
  * 全面切换到 `human_click`。
  * 在答题模块中引入基于文本长度的对数正态认知/阅读延时，取代死板的 `time.sleep(2)`。
* **边界**：保持原有的识别准确率、黑名单机制（如帮派黑名单）、题库匹配及 LLM 接口调用不变，只改造最终产生输入事件的环节。

## 4. 关键核心算法与原型设计

### 4.1 二维截断高斯落点算法
```python
def get_human_click_point(box: list, margin_ratio: float = 0.15) -> tuple:
    """
    在目标识别框内按二维高斯分布生成随机落点
    box: [x, y, w, h]
    """
    x, y, w, h = box
    safe_margin_x = max(2, int(w * margin_ratio))
    safe_margin_y = max(2, int(h * margin_ratio))
    
    min_x, max_x = x + safe_margin_x, x + w - safe_margin_x
    min_y, max_y = y + safe_margin_y, y + h - safe_margin_y
    
    center_x = x + w / 2.0
    center_y = y + h / 2.0
    
    sigma_x = max(1.0, (w - 2 * safe_margin_x) / 6.0)
    sigma_y = max(1.0, (h - 2 * safe_margin_y) / 6.0)
    
    for _ in range(10):  # 截断采样
        rx = random.gauss(center_x, sigma_x)
        ry = random.gauss(center_y, sigma_y)
        if min_x <= rx <= max_x and min_y <= ry <= max_y:
            return int(round(rx)), int(round(ry))
            
    return int(round(center_x)), int(round(center_y))
```

### 4.2 触控物理动态与肌肉微颤
```python
def human_touch_down_up(controller, target_x: int, target_y: int):
    """
    模拟真实人类指腹接触屏幕与按压过程
    """
    controller.post_touch_down(target_x, target_y).wait()
    dwell_time = random.uniform(0.065, 0.125)
    
    # 40% 概率触发按压期间的 1 像素肌肉微抖动
    if random.random() < 0.4:
        time.sleep(dwell_time * 0.5)
        jx = target_x + random.choice([-1, 0, 1])
        jy = target_y + random.choice([-1, 0, 1])
        controller.post_touch_move(jx, jy).wait()
        time.sleep(dwell_time * 0.5)
    else:
        time.sleep(dwell_time)
        
    controller.post_touch_up().wait()
```

### 4.3 跨进程单人注意力锁
```python
class HumanAttentionCoordinator:
    _LOCK_FILE = os.path.join(os.path.dirname(__file__), "..", "data", "attention.lock")
    _LAST_ACTION_FILE = os.path.join(os.path.dirname(__file__), "..", "data", "last_act.stamp")

    @classmethod
    @contextmanager
    def acquire_focus(cls, instance_id: str):
        os.makedirs(os.path.dirname(cls._LOCK_FILE), exist_ok=True)
        with _storage_lock(cls._LOCK_FILE):
            if os.path.exists(cls._LAST_ACTION_FILE):
                try:
                    with open(cls._LAST_ACTION_FILE, "r") as f:
                        last_inst, last_time = f.read().split("|")
                        if last_inst != instance_id:
                            elapsed = time.time() - float(last_time)
                            # 模拟人类鼠标在不同窗口间移动的耗时 (250ms ~ 550ms)
                            required_delay = random.uniform(0.25, 0.55)
                            if elapsed < required_delay:
                                time.sleep(required_delay - elapsed)
                except Exception:
                    pass
            
            yield
            
            try:
                with open(cls._LAST_ACTION_FILE, "w") as f:
                    f.write(f"{instance_id}|{time.time()}")
            except Exception:
                pass
```

## 5. 开发顺序与执行规划

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│   Phase 1    │ ──► │   Phase 2    │ ──► │   Phase 3    │ ──► │   Phase 4    │
│  配置层平替   │     │  核心库开发   │     │  业务层改造   │     │  多号联调验收 │
│ (消除ClickKey)│     │(触控与互斥锁) │     │ (逐个脚本替换)│     │(验证防并发)  │
└──────────────┘     └──────────────┘     └──────────────┘     └──────────────┘
```

### Phase 1：配置层平替（零代码风险）
1. 检查并备份 `assets/interface.json`。
2. 将 `assets/resource/mac/pipeline/ClickkeyChangeClick.json` 复制到 `assets/resource/base/pipeline/`（或在 `interface.json` 的 `resource.path` 中追加挂载）。
3. **验证标准**：启动单号测试“帮派签到”或“宝图任务”，确认原本发送 Alt+按键 的逻辑已完全转变为游戏内图标点击，且界面正常打开。

### Phase 2：核心底层库构建
1. 在 `agent/utils/` 下创建 `human_touch.py`，实现二维高斯随机落点、人手按压微颤抖触控及贝塞尔拟人滑动。
2. 在 `agent/utils/` 下创建 `attention_coordinator.py`，基于 `utils.py` 的文件锁实现跨进程单人注意力调度器。
3. **验证标准**：通过本地测试用例启动双进程调用，验证互斥生效且跨实例调用存在强制物理时延。

### Phase 3：业务层脚本拟人化重构
1. **重构 `returnOCR.py`**：将 `center_x / center_y` 换为高斯随机取点与拟人触控。
2. **重构答题模块（`reco_sjqy.py` & `AIAnswer.py`）**：
   * 移除死板的 `time.sleep(2)`，接入基于字符长度的阅读认知耗时模型。
   * 兜底盲猜选项从固定像素换为第一选项区域的高斯随机点。
3. **重构杂项模块（`shimen_renwu.py`、`sanjieqiyuan.py` 等）**：
   * 消除硬编码坐标。
4. **验证标准**：独立运行三界奇缘与科举乡试，检查日志输出与点击行为，确认落点随机分散且答题耗时自然波动。

### Phase 4：5 账号并发联调与验收
1. 5 个模拟器多开实例统一加载新配置。
2. 启动 5 账号组队日常。
3. **验证标准**：审查运行时综合日志，确认任意毫秒内不存在两个实例同时下发点击指令。

## 7. 模拟器环境与多账号运行指引

为保证代码改造效果最大化，5 个模拟器实例需完成以下一次性环境配置：
1. **杜绝直接克隆母盘**：克隆后必须进入每个模拟器的“设置 $\to$ 属性设置”，依次点击**随机生成机型、随机 IMEI、随机 MAC 地址、随机 Android ID**。
2. **机型多样化配置**：5 个实例分别设定为不同品牌的真实主力机型（如 1 台小米13、1 台 vivo X90、1 台 OPPO Find、1 台荣耀 Magic、1 台华为 Mate），避免 5 账号在服务端的设备指纹聚类雷同。
3. **分辨率与渲染模式保持一致**：所有 5 个实例均需遵循项目既定规范（1280*720 240dpi，显卡渲染模式选择 DirectX）。
